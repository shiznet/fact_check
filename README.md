# Fact-check Skill

一个面向多来源内容的事实核查 Skill。目标是将待核查内容拆解为可验证的具体主张，寻找可追溯的证据，并明确区分已证实、已证伪、部分成立与证据不足的情况。

当前实现覆盖网页、社交媒体内容（包括小红书/RED）、文章、截图与 OCR 文本、文档、研究材料、新闻，以及代码仓库和技术声明。

## 核心原则

- **主张优先**：核查具体事实主张，而不是笼统判断某个作者、账号或来源是否可信。
- **证据可追溯**：尽可能记录来源链接、发布时间/版本、相关原文或数据，以及证据的适用范围。
- **主动寻找反证**：对重要或有争议的主张，同时检索支持和反驳证据。
- **评估来源独立性**：转载、复制内容或共同引用同一上游来源，不视为独立佐证。
- **不把缺证当作证伪**：没有找到证据不代表主张必然错误；证据不足时明确说明。
- **不伪造核查过程**：不得编造来源、引文、日期、工具结果或声称未实际执行的检查。
- **说明限制**：注明无法访问的页面、未核查的主张、OCR 不确定性和工具故障等影响结论的限制。

## 核查流程

1. 明确核查目标、上下文和时间范围。
2. 提取并拆分可验证的事实主张。
3. 根据影响、时效性和复杂度确定核查优先级。
4. 规划检索，寻找相关的原始证据及反向证据。
5. 阅读并评估证据的相关性、可靠性、时效性、方法和独立性。
6. 对每条主张给出有证据支持的判定，并说明关键理由。
7. 输出结论、证据、反证、限制与来源链接。
8. 检查引文与链接是否真实对应已访问的材料，避免过度声称核查覆盖范围。

## 判定标签

| 标签 | 含义 |
|---|---|
| `SUPPORTED` | 现有证据在指定范围内支持该主张 |
| `REFUTED` | 可靠证据实质性地反驳该主张 |
| `MIXED` | 主张部分成立，或因遗漏关键条件而具有误导性 |
| `INSUFFICIENT_EVIDENCE` | 现有证据不足、不可获得或存在无法解决的冲突 |
| `UNVERIFIABLE` | 主张过于模糊、主观，或缺少可行的客观检验方法 |

判定应针对具体主张；必要时注明适用的时间、版本、地区、群体或其他条件。不要为了给出二元答案而强行下结论。

## 工具依赖与限制

本仓库定义核查流程和规则，**不会自动提供搜索、网页读取、社交平台读取、OCR、图像理解或代码仓库访问能力**。运行环境需要提供相应工具；实际使用时只能调用环境中确实可用的能力，并如实披露访问限制或失败情况。

当前文件集是初始模块化实现。尚需结合目标运行环境的 Skill 加载约定进行验证，并通过测试用例检查实际行为；文档中的测试场景不等于已完成自动化测试。

## 使用建议

收到核查请求时，先明确需要判断的主张和上下文；若输入包含多条主张，优先拆分并逐条核查。报告应先给出简明结论，再列出关键证据、反证、来源和限制。高风险或时效性强的主张应采用更严格的证据标准。
